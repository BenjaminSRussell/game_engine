ARCHITECTURE OVERVIEW
================================================================================

GPU-Driven Rendering Pipeline:

  Scene Objects
      ↓ (group by mesh/material/LOD)
  Instance Batching (geometry/instancing/)
      ↓ (organize data for GPU)
  GPU Scene Buffers (rendering/core/gpu_scene.c)
      ↓ (copy to GPU)
  GPU Data Transfer (rendering/core/gpu_data_transfer.c)
      ↓ (dispatch compute)
  Compute Culling Shaders (rendering/shaders/gpu_culling.metal)
      ↓ (generate draw commands)
  Draw Command Generation (rendering/gpu_driven/draw_command_gen.c)
      ↓ (multi-draw indirect)
  GPU Rendering (Metal indirect drawing)

KEY INNOVATION: Zero CPU-GPU stalls for rendering using async compute and
                indirect command buffers

================================================================================
DATA STRUCTURES (OPTIMIZED)
================================================================================

GPUInstanceData (128 bytes) - Cache-aligned:
  • 4x4 transform matrix (64 bytes)
  • AABB bounds (32 bytes)
  • material_id, visibility_flags, mesh_id, custom_data (32 bytes)

GPUMaterialData (64 bytes):
  • Base color RGBA (16 bytes)
  • Metallic/Roughness/AO (16 bytes)
  • 8 bindless texture indices (32 bytes)

IndirectDrawArgs (20 bytes) - Metal-compatible:
  • indexCount, instanceCount, indexStart, baseVertex, baseInstance

CULLING STRUCTURES:
  • FrustumData - 6 plane frustum equations
  • LODSelectionData - Distance thresholds with hysteresis
  • CullingResult - Per-instance visibility and LOD output
  • GPUCounters - Atomic counters for GPU operations

================================================================================
COMPUTE SHADER KERNELS (7 Total)
================================================================================

1. cull_frustum
   - AABB vs 6-plane frustum testing
   - Sets visible_flag per instance
   - ~64 threads per group

2. select_lod
   - Distance-based LOD selection
   - Hysteresis for stability
   - Output: lod_selected per instance

3. cull_additional
   - Optional: occlusion, distance fade, etc.
   - Framework for future features

4. compact_visible
   - Atomic append visible instances
   - Build dense visible list
   - Update draw indices

5. build_batches
   - Group visible instances by material/mesh
   - Framework for batch-based rendering

6. reset_counters
   - Reset atomic counters for new frame
   - Lightweight synchronization

7. populate_indirect_args
   - Fill Metal-compatible indirect draw arguments
   - Set indexCount, instanceCount, baseInstance

INTEGRATION POINTS
================================================================================

1. Batching System
   - geometry_instance_batching_get_batch_data() provides batch info
   - Organizes instances by mesh/material/LOD
   - Feeds into GPU scene for upload

2. GPU Scene Management
   - Accepts instance data from batching
   - Manages GPU buffers
   - Tracks dirty regions for incremental updates

3. Data Transfer
   - Handles CPU→GPU data movement
   - Staging buffers hide transfer latency
   - Framework ready for async transfers

4. Compute Shaders
   - Receives instance/material data from GPU buffers
   - Outputs culling results and indirect draw args
   - Uses atomic operations for coordination

5. Draw Command Generation
   - Processes culling results
   - Generates Metal-compatible indirect draw arguments
   - Ready for multi-draw indirect execution

6. Render Loop (future)
   - Will dispatch compute culling
   - Execute indirect draw calls
   - Profile and collect stats
